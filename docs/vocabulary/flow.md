## What it means

A composed sequence of [skills](skill.md), run in a stated order, with gates and human decision points along the way. A flow is what you get when several skills are chained on purpose — it is not a second copy of the skill folders, just a path drawn through them.

## In this fork

`/standup-prep` is a flow: it chains preflight → context → guidelines → sweeps → brief. `/implement-tickets` is a flow that loops `/implement` across a dependency frontier. This fork's own overview stages (Start the day → Shape it → Build it → Land it → When it breaks → Sweep for debt → Close the session) are flows too — a second way to navigate the same skills, not a second set of them.
